# GSTN GSTR-1 official reference review

**Review date:** 2026-11-03  
**Purpose:** Record what the currently accessible official GSTN material verifies before implementing a GSTN upload JSON generator.

## Official sources checked

1. GSTN, *FAQs and User Manual – Returns Offline Tool*:  
   https://tutorial.gst.gov.in/downloads/invoiceuploadofflineutility.pdf
2. GST Portal, *Creation of Outward Supplies Return in GSTR-1*:  
   https://tutorial.gst.gov.in/userguide/returns/Creation_of_Outward_Supplies_Return_in_GSTR-1.htm

The PDF is an official GSTN user manual and describes the Returns Offline Tool, its Excel workbook, section-wise CSV templates, JSON generation and portal upload. The online GSTR-1 guide confirms that the portal's PREPARE OFFLINE flow accepts JSON prepared through the offline tools.

## Verified implementation facts

- The offline utility is downloaded from GST Portal > Downloads > Offline tools > Returns Offline tool. The downloaded package includes the utility, workbook template, section-wise CSV templates, readme and user manual.
- GSTN's manual says the offline utility is desktop/laptop-only; it is not mobile-compatible.
- The utility supports section-wise preparation/import and generates JSON for upload. The taxpayer must still upload it through the GST Portal, generate/review the return summary and submit using DSC or EVC. SRK must not represent local JSON generation as filing/submission.
- The manual documents the major GSTR-1 tables, including B2B/SEZ/DE, B2CL, B2CS, credit/debit notes, exports, advances and adjustments, nil/exempt/non-GST supplies, HSN summary, documents issued, e-commerce supplies and amendments.
- For return periods from August 2024, the official manual describes B2CL as inter-State supplies to unregistered persons with invoice value **more than ₹1,00,000**. For periods up to July 2024, it describes the earlier **more than ₹2,50,000** threshold. B2CS uses the corresponding lower/equal threshold and intra-State unregistered supplies.
- The manual describes a 5 MB maximum for the sum of line items in an offline return file. The utility's own current release and validation remain authoritative for an actual filing attempt.

## Version/schema status — NOT VERIFIED

The accessible official PDF is a user manual, not a versioned machine-readable JSON schema. It does not, in the material reviewed, establish the currently deployed Returns Offline Tool release number, a schema version identifier, or a complete upload-JSON contract.

Therefore:

- Do **not** hard-code a guessed version such as a version mentioned by a third-party vendor.
- Do **not** infer the upload JSON structure from portal round-trip/download JSON or third-party examples.
- Do **not** describe SRK CSV exports, classification reports or any future locally serialized JSON as GSTN-upload-ready until it is checked against the matching official utility/schema.
- Do not mark GSTN compatibility as complete based solely on passing SRK unit tests.

## Required next evidence before implementation

2. Record the package filename, release/version shown by the utility/readme, download date and official source URL.
3. Preserve redacted official sample/template files and sample JSON generated by that exact utility release, where available.
4. Map supported SRK source fields to the utility's actual sections and required fields. Implement only sections for which SRK has complete source data.
5. Add explicit blocking validation for unsupported/incomplete sections rather than silently omitting data.
6. Build deterministic serializers and positive/negative fixtures from those official files.
7. Open generated test files in the same official utility and record the validation result before calling the output upload-ready.

## Current SRK boundary

The current GSTR-1 classifier covers core domestic B2B/B2CL/B2CS classification. Existing invoice/HSN CSV exports are management/review reports. `GstReturnReadiness` is a preflight aid and explicitly does not generate GSTN upload JSON. Those features must retain that boundary until the evidence and validation steps above are completed.
